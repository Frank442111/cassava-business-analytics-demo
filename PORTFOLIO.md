# Cassava Analytics — Simulated Portfolio Demonstration

## Problem

Small trading operations need a clear view of sales, estimated costs, unknown
expenses and stock assumptions. Repeated dates, missing observations and short
histories can otherwise produce misleading summaries or forecasts. This project
demonstrates how to make those assumptions visible in an interactive dashboard.

The public portfolio uses **only wholly fictional transactions and opening stock**.
The data are newly generated by deterministic arithmetic, not copied, anonymized
or transformed from a real ledger. No personal information, real sales figures,
private paths, credentials or business records are included in the demo.

## Tools and structure

- Python: pure functions, Decimal money calculations, validation and unittest.
- Streamlit: accessible labels, filters, tabbed exploration and in-memory downloads.
- Pandas and NumPy: daily aggregation, calendar features and numeric evaluation.
- Altair: interactive simulated sales and actual-versus-predicted charts.
- scikit-learn: LinearRegression, StandardScaler and regularized Ridge pipelines.
- AST and runtime guards: checks that demo source has no private imports or file APIs.

This standalone repository contains only the fictional portfolio demonstration. Its modules
generate a fictional scenario, calculate fictional KPIs, compare learning models
and render the read-only interface. It does not import the private application.
The separate private application remains local and is not part of the public artifact.

## Features and analytical methods

The invented scenario contains 112 transactions across 56 complete fictional
days, beginning 2032-04-01, and 12,000 kg fictional opening stock. Dates and values
are generated afresh on each run without a CSV. RWF revenue is quantity × price;
the estimated COGS assumes a fictional fixed purchase price and 1:1 resale.
Unknown additional expenses remain unknown unless a viewer chooses an explicit
fictional zero-expense scenario. Full-scenario stock is independent of date filters.

Visitors can filter fictional dates, compare simulated quantities, inspect a
fictional transaction table and download an explicitly labeled fictional CSV.
No form saves records, no upload accepts real data, and no shared database or
filesystem stores viewer inputs. A failed fictional generator stops the demo
instead of selecting another dataset.

## Simulated forecasting

Moving Average and basic day-number Linear Regression provide baselines.
Enhanced Ridge adds weekly sine/cosine features, lag 1/7 and a seven-day rolling
mean built strictly from earlier values. The first 42 fictional days train models;
the last 14 form a common chronological test period. Preprocessing is fitted on
training rows only. Ridge forecasts recursively, so actual test sales never enter
later lag features. All models receive the same test dates and no held-out updates.

Mean Absolute Error measures average absolute prediction error in kg/day.
The interface computes scores from held-out observations; no winner is hardcoded.
Regularization may reduce noise fitting or may underfit; additional features do
not guarantee improvement. Privacy tests and leakage tests verify these boundaries.

## Limitations and skills demonstrated

The example is deterministic, small, fictional and has a deliberately simple
weekly structure. It cannot validate performance on an actual business. Short
real histories are insufficient for reliable forecasting; no purchasing advice,
audited profit, physical inventory assurance or forecast uncertainty is supplied.
Transaction profit excludes shared overhead, taxes and financing. There is no
authentication, because only fictional content belongs in the public demo.

The work demonstrates financial aggregation, explicit missing-data semantics,
time-series feature engineering, chronological evaluation, leakage prevention,
regularization, interactive reporting, dependency separation, regression testing,
and privacy by separating the publishable artifact from operational records.

Publication remains a future action requiring explicit owner approval. A hidden
or unlisted URL is not authentication and cannot protect real business data.
